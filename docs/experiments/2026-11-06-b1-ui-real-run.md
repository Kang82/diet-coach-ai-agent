# 식단표 화면에서 실제 생성 1회 (2026-11-06)

## 질문

- 화면(B1: T2-1~T2-3)에서 버튼을 눌러 실제 모델로 식단표가 끝까지 나오나
- 바깥 턴(모델이 도구를 고르는 호출)은 얼마나 쓰나. `useResponseFinish`의 응답 사용량에 도구 안 `harness.prompt` 사용량이 들어가나 (tasks.md T2-2)

## 방법

- 개발 서버(`npm run dev -- --port 5199`), `.dev.vars`의 가짜 모드(`PLAN_GENERATOR=demo`)를 끈 상태
- 브라우저에서 `/` → "식단표 만들기". 프로필은 페르소나 A, 모델은 gemma(`@cf/google/gemma-4-26b-a4b-it`)
- 도구 입력의 `weekStart`는 이번 묶음에서 없앴다. 시작일은 도구가 `nextMondayKst`로 정한다
- 원본: [data/2026-11-06-b1-ui-real-run.json](data/2026-11-06-b1-ui-real-run.json)

## 비용

약 288 Neuron (도구 안 식단 생성 286 + 바깥 턴 2), 3분 7초

## 결과

| 걸린 시간 (도구) | 식단 생성 입력 / 출력 토큰 | Neuron (식단 생성) | 바깥 턴 입력 / 출력 토큰 | Neuron (바깥 턴) | `checkPlan` | 다시 추천 |
| --- | --- | --- | --- | --- | --- | --- |
| 3분 7초 | 1,928 / 9,827 | 약 286 | 17 / 75 | 약 2 | 처음에 통과 | 0회 |

- 화면: 기다리는 화면 → 식단표가 정상으로 나왔다. 진행 중 새로고침해도 경과 시간과 진행 상태가 이어졌다(가짜 모드에서 확인).
- **응답 사용량(`useResponseFinish`)에는 도구 안 `harness.prompt` 사용량이 들어가지 않는다.** 바깥 턴만 센다. 따라서 하루 사용량은 "응답 사용량 + 도구 결과의 `stats.usages`"로 세야 한다 (T7-3).
- 바깥 턴 입력이 17토큰으로 시스템 프롬프트보다 작게 나왔다. Workers AI가 보고하는 값이 실제 과금과 같은지는 대시보드와 비교해 봐야 한다.
- 메뉴 다양성은 좋았다. 백반 2회(월·금) 외에는 모두 다른 메뉴.
- 태그: 백반에 또 `soy`가 붙었다(T1-5, T1-6에서도 봄). 삼겹살 구이에는 `fatty_meat`가 맞게 붙었다.
- 제목에 주문 팁이 괄호로 들어간다("백반 (생선 반찬 고르기)"). 주문 팁 칸과 같은 말이 화면에 두 번 나온다.

## 결론과 영향

- B1 완료 기준을 실제 모델로 확인했다. 1회 예산은 계속 약 250~290 Neuron으로 본다.
- 바깥 턴은 1회 약 2 Neuron이라 비용은 작지만, 안전선(스펙 11.4-3, T7-3)은 두 사용량을 더해 센다.
- 도구 입력에서 `weekStart`를 뺐다. 가짜 모드 확인 때 gemma가 오늘 날짜(금요일 2026-11-06)를 넣어 월요일 칸에 금요일 날짜가 붙었다.
