# B9 첫 배포 확인: 배포본에서 평가 세트 1회 (2026-11-06)

## 질문

- 배포한 Worker(https://diet-coach.jjangyeesoo1.workers.dev)에서 토큰, 원격 D1, Workers AI가 함께 동작해 인터뷰 → 메뉴 분류 → 식단표가 끝까지 나오나
- 한도 보호 카운터(D1 `usage_daily`)가 실제 사용량을 비슷하게 세나

## 방법

- `npm run issue-token -- --remote --origin <배포 주소>`로 원격 사용자 1명을 발급
- `EVAL_RUNS=1 DIET_COACH_URL=<배포 주소>/agents/diet-coach DIET_COACH_TOKEN=<토큰> npm run evals -- -t 페르소나A`
- 평가 세트는 저장 동의 없이 제출한다(`src/evals/support/prepare.ts`). 그래서 D1에 프로필·식단표는 남지 않는다
- 끝난 뒤 `npx wrangler d1 execute diet-coach --remote`로 `usage_daily`, `profiles`, `plans`를 읽음
- 원본: [data/2026-11-06-b9-first-deploy.json](data/2026-11-06-b9-first-deploy.json)

## 비용

D1 카운터 기준 약 508 Neuron(바깥 턴, 목표 메모 확인, 분류, 식단표 모두 포함). 평가 전체 약 5분.

## 결과

| 단계 | 결과 |
| --- | --- |
| 평가 세트 | 통과 (2개 테스트, 300초) |
| 식단표 | 237초, 다시 추천 1회 뒤 통과, 위반 없음 |
| 식단 생성 토큰 | 입력 2,198 / 출력 8,378 + 다시 추천 입력 5,274 / 출력 3,895 → 403 Neuron |
| D1 `usage_daily` | 사용자 메시지 3회, 전체 507.7 Neuron |
| D1 `profiles`, `plans` | 0, 0 (동의 없는 제출이라 저장하지 않음, 규칙대로) |

- 처음으로 다시 추천이 1회 돌았다. 다시 추천 호출만 약 155 Neuron이라 식단표 1회 예산은 다시 추천이 있으면 약 400으로 본다.
- 카운터의 507.7은 식단 생성 403에 분류·목표 메모 확인·바깥 턴 약 100이 더해진 값이다. B6 실측(분류 181, 메모 39, 바깥 턴 약 70)보다 분류가 적게 나왔다. 카운터가 실제보다 크게 세는 방향의 문제는 보이지 않는다.
- 배포 직후 몇 초 동안 토큰 없는 요청이 404, `/api/me`가 Cloudflare 에러 1042를 돌려줬다. 다시 보내니 401, 200으로 정상이었다(전파 중).

## 결론과 영향

- 첫 배포 확인 완료(T7-4). 배포본도 개발 서버와 같은 흐름으로 동작한다.
- 한도 보호 카운터는 실제 사용량을 셀 수 있다. 8,000 안전선이면 하루에 이 흐름을 약 15회 돌릴 수 있다.

## 남은 의문

- 화면에서 동의하고 진행했을 때 원격 D1에 프로필·식단표가 남는지는 로컬(가짜 모드)에서만 확인했다. 사용자가 링크로 확인한다.
