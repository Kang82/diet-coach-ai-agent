# B28 체크 반영 생성 실제 확인 (2026-11-10)

`docs/tasks.md` T28-5. 지난주 체크를 생성 프롬프트에 선호로 넣은 뒤(Task2 R3) 실제 모델로 끝까지 도는지, 결과가 어떻게 바뀌는지 본다.

## 방법

- 로컬 개발 서버(5199), 식단 생성 gpt-oss-120b(low), 데모 모드 끔. 스크래치 스크립트가 `src/evals/support/agent-http.ts`로 메시지를 보냈다
- 페르소나 A, 저장 동의 켬, 분류는 `classesA`로 덮어씀(평가 세트와 같은 방식)
- 1회차(기준): 인터뷰 → 분류(gemma) → 만들기. 시작 월요일 2026-11-16
- 1회차 대화를 "지난주"로 만들려고 로컬 D1 `conversations.plan_week_start`만 2026-11-09로 바꿈(두 만들기가 같은 주라서). 4칸 체크: 수 점심 쌀국수, 목 점심 회덮밥, 화 저녁 연어 구이, 수 저녁 두부 야채 볶음
- 2회차(반영): 새 대화, 분류는 1회차 분류를 `known`으로 넘겨 모델 호출 없음 → 만들기
- 처음 시도는 로컬 Neuron 안전선(8,000)에 걸려 429 `global_daily_limit`. 로컬 `usage_hourly`에 전날 13시(UTC) 칸 5,689가 남아 있었다(계정 GraphQL 최근 24시간은 1,586). 14:00 UTC에 그 칸이 빠진 뒤 같은 대화에 만들기만 이어 보냄

## 결과

- 저장: `plans.conversation_id`에 1회차 대화 ID가 들어감(seq 1). `history` step이 지난주 대화·체크 4칸·저장한 식단표를 읽음
- 프롬프트 입력 +190토큰(지난주 기록 절)
- 2회차 안내 맨 앞에 지난주 반영 문구. 날짜가 "11/16~"로 나와(로컬에서 대화 시작일만 바꾸고 저장한 식단표 본문은 11/16) 안내 날짜를 고른 대화의 시작 월요일로 쓰게 고쳤다(`loadLastWeekQuietly`)
- 먹은 4개 메뉴가 모두 다시 들어감(쌀국수 화, 회덮밥 수, 연어 구이 월, 두부 야채 볶음 화). 앞쪽 요일로 옮겨짐
- 다만 1회차에도 네 메뉴가 모두 있었다. 페르소나 A는 평일 점심 외식 메뉴가 5개뿐이라 매주 다섯 개가 다 들어가고, 집밥도 두 회차가 12칸 중 10칸 같은 메뉴였다(소고기 불고기 → 소고기 무국만 다름). 체크하지 않은 삼겹살 구이·닭다리 달콤 매운 구이도 그대로 남았다
- 결론: 흐름(저장 → 읽기 → 프롬프트 → 안내)은 실제로 동작하고 시간·통과에 문제 없음. 선호가 메뉴 선택을 바꾸는 효과는 이 프로필·1회로는 보이지 않았다. 효과는 배포 뒤 측정(B26 기준 2, 고친 칸 수)으로 본다
