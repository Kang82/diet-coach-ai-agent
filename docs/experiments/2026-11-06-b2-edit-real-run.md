## 결과

- 토요일 저녁만 바뀌었다: 삼겹살 수육(집밥 40분) → 해산물 채소 찜(기름기 없이 담백하게, 집밥 20분). 이유에 요청("돼지고기보다 포화지방이 적은 해산물")이 반영됐다. `changed`는 그 칸 하나, `unchangedTargets`는 없음.
- 첫 시도에 통과(다시 추천 1회 = 사용자 요청 회차). 바뀐 식단표도 `checkPlan`을 통과한다.
- 화면: 알림 "토요일 저녁을 바꿨어요.", 바뀐 칸에 테두리 강조. 수정 중 새로고침해도 진행 상태와 경과 시간이 이어졌다(가짜 모드에서 확인).
- 칸 수정의 출력 토큰(3,497)이 1주일 생성(7,390)의 절반쯤이다. 1칸만 만드는데도 추론이 길다(스펙 11.5의 "2칸만 만들어도 1분 이상"과 같은 경향).
- **바깥 턴 입력이 대화가 길어질수록 커진다.** 칸 수정 턴의 입력이 2,234토큰으로, 앞 도구 결과(식단표 전체 JSON)가 모델 문맥에 다시 들어가기 때문이다. 지금은 약 21 Neuron이지만 칸을 여러 번 고치면 계속 는다.
- 가짜 모드 확인 중 한 번, 만들기 응답이 약 2분 늦게 시작했다(사용자 메시지 03:25:39, 응답 시작 03:27:43). 오류 로그는 없었고 도구는 정상으로 끝났다. 원인은 모른다(모델 대기 또는 Flue의 재시도로 추정). 실제 모드에서는 1~2초 안에 시작했다.

## 결론과 영향

- B2 완료 기준(칸 하나만 바뀜)을 실제 모델로 확인했다. 칸 수정 1회 예산은 약 120~140 Neuron(바깥 턴 포함), 약 1분으로 본다.
- 바깥 턴 문맥이 커지는 문제는 tasks.md "나중에"에 남겼다. 도구 결과를 모델에게는 짧게 보여 주는 방법(예: 모델용 요약과 화면용 데이터 분리)을 찾아볼 일이다.
