# B13 한도 보호 보강 로컬 확인 (2026-11-08)

B13(T10-2~5)에서 바꾼 것(메시지 종류에 맞는 도구 하나만 마운트, 종류별 하루 횟수, 진행 중 예약)이 개발 서버에서 실제 바깥 모델과 함께 동작하는지 확인했다. 식단 생성과 분류는 데모(가짜)라 Neuron을 쓰지 않는다.

## 질문

- 분류·만들기·칸 수정 메시지에서 그 도구만 불리나. 자유 문장("식단표 만들어 줘")에는 도구가 불리지 않나
- 도구가 끝나면 진행 중 예약(`usage_reservations`)이 비나
- 만들기 6번째가 `user_kind_limit`로 막히나. 종류별 카운터가 맞게 쌓이나

## 방법

- 로컬 개발 서버(5199), `.dev.vars`에 `PLAN_GENERATOR=demo`, `MENU_CLASSIFIER=demo`(끝난 뒤 되돌림). 로컬 D1에 0004 적용
- 페르소나 A로 인터뷰·분류를 채운 대화 1개(`src/evals/support/prepare.ts`)에 만들기 → 칸 수정 → 자유 문장 → 만들기 4번 → 만들기 6번째(POST만)
- 대화 스냅샷의 도구 부분, 로컬 D1 `usage_daily`·`usage_reservations`를 봄

## 비용

바깥 턴만 실제 모델. 메시지 10개(인터뷰 제출은 LLM 없음). 약 20 Neuron 이하로 어림(카운터를 지워서 확인 안 함).

## 결과

- 처음 돌렸을 때 만들기가 `global_daily_limit`로 막혔다. 로컬 `usage_hourly` 최근 24시간 합계가 7,046(B11 실측 때 쌓인 양)이라 만들기 예약 1,200을 더하면 8,000을 넘었기 때문이다. 예전 규칙(합계만 봄)이면 통과했을 요청이다. 예약이 의도대로 막은 것으로 보고, 로컬 카운터 세 표를 지우고 다시 돌렸다
- 다시 돌린 결과

| 메시지 | 도구 | 결과 |
| --- | --- | --- |
| 만들기 1 | `create_week_plan` | ok, 12초 |
| 칸 수정 | `edit_plan_cells` | ok, 12초 |
| 자유 문장 "식단표 만들어 줘" | 없음 | 모델이 "화면의 '식단표 만들기:' 버튼을 눌러 주세요."라고 답함, 43초 |
| 만들기 2~5 | `create_week_plan` | 모두 ok, 12~14초 |
| 만들기 6 | (미들웨어) | 429 `user_kind_limit` "오늘 식단표 만들기는 5번까지예요. 오전 9시 이후에 다시 할 수 있어요." |

- 끝난 뒤 `usage_reservations`는 비었다. `usage_daily`: `user:` 9, `classify:` 1, `plan:` 5, `edit:` 1
- 도구가 바뀌는 제출마다 Flue가 `role: system`, `display: diagnostic` 메시지("System instructions updated. New tool available…")를 대화에 넣는다. 화면은 대화 메시지를 그리지 않고 도구 결과로만 상태를 정하므로 영향이 없다. 바깥 모델 입력 토큰이 조금 는다
- 자유 문장 턴이 43초로 길었다(도구 없이 gemma가 추론한 시간). 화면은 늘 접두어 메시지를 보내므로 실제 사용 경로는 아니다

## 결론

- 종류별 도구 마운트, 종류별 하루 횟수, 예약과 정산이 개발 서버에서 동작한다
- 같은 응답 병렬 호출(게이트)은 gemma가 병렬 호출을 내지 않아 실제로 확인하지 못했다. 단위 테스트(게이트, 화면이 `duplicate`를 건너뜀)로만 확인했다
- 배포본 확인은 B12와 함께 실제 1회 때 한다(원격 `usage_reservations`가 끝난 뒤 비는지, `usage_daily`에 `plan:<userId>`)
