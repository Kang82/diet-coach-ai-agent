# B15 불가능한 프로필 사전 점검과 같은 메뉴 횟수 조정 실제 확인 (2026-11-08)

B15(T11). 외식 메뉴가 적어 규칙상 불가능한 프로필(배포본 사용자 실패의 원인)을 LLM 전에 막고, 메뉴가 적지만 가능한 프로필은 같은 메뉴 허용 횟수를 늘려 만들게 했다. 코드(`2cbeee6`)가 개발 서버에서 실제로 그렇게 동작하는지 두 가지를 확인했다.

## 방법

- 커밋 `2cbeee6` 상태, 로컬 개발 서버. `MENU_CLASSIFIER=demo`(분류는 가짜, 픽스처 분류로 덮어씀). 식단 생성은 기본값(gemma, 추론 medium). 로컬 카운터를 비우고 새 토큰을 발급
- **페르소나 F**(배포본 사용자 프로필 모양만 본뜸, 실제 값 아님): 평일 점심 외식 2개(1개 주 1회), 평일 저녁 외식 3개(1개 주 1회), 일정 없음. 인터뷰 제출 → 분류 요청 → 만들기를 보내고 `create_week_plan` 결과를 읽음(일회성 스크립트, `prepareConversation` 재사용). 10:35 KST
- **페르소나 G**: 평일 점심 외식 2개(비빔밥, 칼국수), 저녁·주말 집밥, 감량. `EVAL_RUNS=1 npm run evals -- -t 페르소나G` 1회. 10:35~10:38 KST
- 원본: [data/2026-11-08-b15-persona-f-infeasible.json](data/2026-11-08-b15-persona-f-infeasible.json), [data/2026-11-08-b15-persona-g-gemma.json](data/2026-11-08-b15-persona-g-gemma.json)

## 비용

로컬 `usage_hourly` 합계 약 323 Neuron. G 식단 생성 242(입력 1,801 / 출력 8,276) + 바깥 턴 6번 약 81. F는 바깥 턴만(약 40). 시작 전 남은 양을 약 1,390으로 어림했으므로 약 1,070이 남는다(GraphQL로 직접 확인은 안 함)

## 결과

| 항목 | 페르소나 F (불가능) | 페르소나 G (같은 메뉴 3번) |
| --- | --- | --- |
| 만들기 걸린 시간 | **4초** | 161초 (생성 153초) |
| 도구 호출 | `create_week_plan` 1번 | 1번 |
| 결과 | `infeasible`, 식단 생성 LLM 호출 없음 | `ok`, 첫 생성 통과, 다시 추천 0 |
| 안내 | "평일 점심 외식 메뉴가 적어 규칙에 맞는 식단표를 만들 수 없어요. 평일 점심에 외식 메뉴를 더 넣어 주세요." | "외식 메뉴가 적어 같은 메뉴를 1주일에 3번까지 넣었어요." |

- F: 테스트에서 계산한 대로 일정이 없으면 평일 점심만 모자란다(`shortMeals: [평일 점심]`). 배포본에서 같은 모양이 5~6분, 출력 약 15,000토큰을 쓰고 실패하던 것이 LLM 없이 바로 끝났다
- G: 평일 점심 5칸을 비빔밥(월·수·금)·칼국수(화·목)로 번갈아 채웠다. 늘린 횟수(3번)와 연속 금지를 모두 지켰고, 예전 규칙(주 2번)이었다면 비빔밥 3번째가 위반이다(`experiments-recheck.test.ts`에 둘 다 넣음). 출력 8,276토큰은 페르소나 A~D 범위(5,700~10,700) 안
- 외식 5칸 모두 주문 팁이 있었다(B14 비교에서는 대부분 비었음). G 픽스처 분류에 메뉴마다 팁이 있고 메뉴가 2개뿐이라 그런 것으로 보인다. 제목 괄호(“비빔밥 (나물 위주로)”)는 여전하다

### 품질 메모 (사람 확인 필요)

- 일요일 점심 "요거트와 과일 (달콤한 맛)" 이유가 "적당한 당분 섭취로 스트레스를 풀되 양을 조절합니다"로 감량 목표 근거가 약하다
- 토요일 점심 돈까스는 튀김 1번 허용 안이지만 감량 프로필 주말 집밥으로는 어색하다. 규칙 위반은 아님

## 결론

- 사전 점검은 실제 대화 흐름에서도 의도대로 동작한다: 불가능하면 4초 만에 모자란 끼니를 안내하고 식단 생성 Neuron을 쓰지 않는다. 메뉴가 적지만 가능한 프로필은 늘린 횟수를 프롬프트·점검·안내가 같이 써서 첫 생성에 통과했다
- 배포본 사용자는 이 코드를 배포한 뒤 다시 만들면 "평일 점심(또는 저녁) 메뉴를 더 넣어 달라"는 안내를 받는다(화요일 점심 일정이 있으면 점심·저녁 둘 다 안내). 배포는 사용자 확인 뒤
- 한 번씩만 돌렸다. G의 흔들림은 평가 세트를 돌릴 때 함께 본다
