# 인터뷰 실제 측정 (2026-11-06)

## 질문

- B4 인터뷰 턴(`interview_turn` 도구: 추출 `harness.prompt` → `applyTurn` → 코드 문장)은 실제 모델로 턴마다 시간과 Neuron이 얼마나 드나
- 계획의 멈춤 기준: 턴당 60초 또는 60 Neuron을 넘으면 멈추고 다시 정한다

## 방법

- 개발 서버, gemma, 기획서 예시 답. 스크립트가 질문 문장을 보고 답을 고른다(목표 → 약 → 피할 음식 …)
- 처음 2턴만 돌렸다. 추론 수준을 바꿔 가며 세 번 돌렸다
  1. Flue 기본값(`medium`). 이전 세션의 개발 서버가 5199에 남아 있어 요청이 그쪽으로 갔다
  2. `thinkingLevel: 'off'`(추출 호출과 인터뷰 중 바깥 턴). 서버 하나로 다시 띄움
  3. `thinkingLevel: 'low'`
- 원본: [data/2026-11-06-b4-interview-real-run.json](data/2026-11-06-b4-interview-real-run.json)

## 비용

약 1,110 Neuron, 약 11분 (gemma 세 번, 각 2턴) + 추출 모델 비교 약 260 Neuron (실패한 호출 사용량은 기록되지 않아 어림)

- **추출 1회의 출력이 4,600~7,000토큰이다.** "없어요" 한 마디를 `{ filled: { medication: "none" } }`로 옮기는 데도 7,000토큰, 약 200 Neuron이 들었다. 추론 수준을 바꿔도 줄지 않았다.
- `'off'`는 Workers AI에 전달되지 않는다. Flue의 Workers AI 공급자(`@flue/runtime/dist/cloudflare/workers-ai-provider.mjs`의 `applyReasoningEffort`)는 low~high일 때만 `reasoning_effort`를 보내고, `'off'`면 아무것도 보내지 않아 모델 기본 추론이 그대로 돈다. `'low'`는 `"low"`로 보내지만 추출 출력은 줄지 않았다.
- 바깥 턴은 추론을 줄이자 6~12 Neuron이 됐다(기본값에서는 67).
- 1턴 추출 입력이 5,951~8,612토큰으로 프롬프트(약 1,600)의 몇 배다. Flue가 스키마 검증 실패 뒤 다시 요청한 것으로 보이지만 무엇이 실패했는지는 보지 못했다(harness 대화는 클라이언트 대화에 나오지 않음).
- 추출 결과는 맞았다. 목표 두 개와 약 "없음"을 바르게 뽑았고 다음 질문도 맞았다. 맞장구(ack)도 자연스러웠다.
- 실행 1의 도구 실패(interrupted)는 개발 서버가 두 개 떠 있던 탓일 수 있다. 실행 2, 3에서는 다시 나오지 않았다. 실패한 턴에서 바깥 턴 모델은 도구 대신 직접 질문 목록을 썼다. 지시문에 "도구가 실패해도 직접 답하지 말 것"을 넣었다.

### 추론하지 않는 모델로 추출 (같은 날, 첫 턴 1회씩)

`.dev.vars`의 `INTERVIEW_MODEL`로 추출 모델만 바꿨다(바깥 턴은 gemma `low`). 단가는 Workers AI 가격표(2026-10-20 갱신)에서 옮겼다.

| 모델 | 결과 | 추출 시간 | 추출 입력 / 출력 | 추출 Neuron |
| --- | --- | --- | --- | --- |
| granite-4.0-h-micro | 400 `Bad input`. Flue가 보내는 메시지 형식(content 배열·null)을 받지 않음 | - | - | 0 |
| mistral-small-3.1-24b | Flue `finish` 대신 포기("사용자 답을 읽지 못했습니다") | - | 기록 없음 | 약 50 이하로 어림 |
| llama-4-scout-17b | 성공. 목표 두 개를 맞게 뽑고 다음 질문(약)으로 감. 맞장구는 없음 | **5초** | 6,017 / 48 | **151** |

- llama-4-scout는 빠르고 출력이 짧지만 입력 단가가 gemma의 2.7배라 Neuron은 줄지 않았다. 입력 6,017토큰은 gemma 2턴째(1,629)의 3.7배다. 스키마 재요청이 있었는지, 한국어가 토큰을 더 쓰는지는 모른다.

### 바꾼 방식: 화면 입력 + 목표 메모 확인 (같은 날)

정해진 답은 화면 입력으로 받고, LLM은 제출할 때 목표 메모만 llama-4-scout로 1회 확인한다. 프롬프트를 짧게 줄였다(`core/interview-note.ts`). 페르소나 A 초안을 메모만 바꿔 `인터뷰 제출:` 메시지로 보냈다.

| 메모 | 결과 | 전체 | 메모 확인 입력 / 출력 | 메모 확인 Neuron | 바깥 턴 Neuron |
| --- | --- | --- | --- | --- | --- |
| "체중 5kg 감량, 콜레스테롤 관리" | done | 6초 | 1,489 / 27 | 39 | 9 |
| "한 달에 10kg 빼고 싶어요" | 목표 다시(무리한 목표). 선택지 "한 달에 2kg 감량", "건강한 식습관" | 4초 | 1,486 / 33 | 39 | 10 |
| "근육을 키우고 싶어요" | 목표 다시(지원하지 않는 목표). 선택지 지원 목표 3개 | 6초 | 1,483 / 23 | 38 | 11 |

- 세 경우 모두 맞게 분류했다. 제출 1회에 약 48~50 Neuron, 4~6초. 메모가 없으면 LLM을 부르지 않아 바깥 턴(약 10)만 든다.
- 프롬프트는 약 400자인데 입력이 약 1,500토큰이다. 나머지는 Flue가 붙이는 시스템 프롬프트와 `finish` 도구 스키마로 보인다.
- 화면으로도 페르소나 A 답을 끝까지 1회 진행했다(Chrome). 제출 뒤 약 10초에 요약과 "식단표 만들기"가 나왔다. 메뉴를 2개만 넣으면 한 번 더 묻고, 새로고침해도 같은 단계에서 이어졌다.

## 결론과 영향

- 매 턴 LLM이 답을 옮기는 방식은 1턴에 약 1~2.5분, 약 190~250 Neuron이라 7~9턴이면 약 1,500~2,000 Neuron이 든다. 식단표 생성(약 250 Neuron)보다 훨씬 비싸서 버렸다.
- **정해진 답은 화면 입력, LLM은 목표 메모 확인 1회**로 바꿨다 (tasks.md T4-4, 스펙 4.1). 인터뷰 1회 약 10~50 Neuron, 제출 대기 10초 안쪽.
- 추론하지 않는 모델 셋 중 Flue로 동작한 것은 llama-4-scout 하나였고, 시간은 5초로 줄었지만 Neuron은 줄지 않았다(턴당 약 150 + 바깥 턴).
- 인터뷰 중 바깥 턴은 `thinkingLevel: 'low'`로 둔다(`src/agents/models.ts`의 `INTERVIEW_THINKING`). 식단표 단계는 기본값 그대로다.

## 남은 의문

- 추출 출력 수천 토큰의 내용(추론인지, finish 도구 재시도인지). harness 대화를 볼 방법을 찾아야 한다
- Workers AI의 gemma에서 추론을 아예 끄는 방법(`reasoning_effort` 다른 값, 다른 모델)
