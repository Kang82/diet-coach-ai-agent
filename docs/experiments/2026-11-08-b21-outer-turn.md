# B21 바깥 턴 비용 보호 로컬 확인 (2026-11-08 ~ 11-09)

## 목적
2차 보안 리뷰(tasks.md T19-6·7)로 바꾼 것이 실제 모델에서도 동작하는지 본다.
- 접두어 없는 메시지(chat) 거절
- 바깥 턴 요청을 system + 이번 사용자 메시지부터로 자르기, 출력 상한 2,048(`output-caps.ts` `fitRequest`)
- 바깥 턴 추론 low로 통일
- 예약 key를 사용자 ID로, 사용자당 비싼 요청 하나(429 `busy`), 응답이 끝나면 예약 한 번 더 지우기
- 목표 메모 확인 프롬프트 첫 줄 `FINISH_ONLY`

## 방법
- 로컬 개발 서버(5199), `.dev.vars`에 `PLAN_GENERATOR=demo`, `MENU_CLASSIFIER=demo`. 바깥 턴과 목표 메모 확인만 실제 모델을 부른다
- 스크립트(세션 스크래치패드, 프로젝트 밖)로 페르소나 A: 인터뷰 전 분류 요청 → chat → 인터뷰 제출 → 분류 → 만들기(도는 중 다른 대화로 분류 요청) → 칸 수정 2회
- 목표 메모 "한 달에 2kg 정도 천천히 빼고 싶어요"로 인터뷰 제출만 6회

## 비용
- 우리 카운터(로컬 D1 `usage_hourly`) 약 650 Neuron(11-08T20 UTC 357, 11-09T11 UTC 297). 계획 어림(30~60)보다 컸다: 목표 메모 확인 6회(llama-4-scout 1회 약 40), 아래 버그 두 개를 찾느라 흐름을 세 번 돌렸다. 시작 전 GraphQL 최근 24시간 합계 3,236

## 도중에 찾아 고친 것
1. **예약 누수(사용자를 20분 막음).** 인터뷰가 끝나기 전에 분류 요청을 보내면 분류 도구가 마운트되지 않아 예약이 정산되지 않았다. key가 사용자 ID라 그 사용자의 비싼 요청이 만료(20분)까지 모두 `busy`. → `diet-coach.ts`의 `useResponseFinish`에서 비싼 종류면 예약을 한 번 더 지운다(이미 없으면 아무 일도 없음)
2. **기록 자르기가 이번 요청을 지움.** Flue는 사용자 메시지 뒤에 `<signal type="instructions">`, `<signal type="resources">`를 user 역할로 붙인다. "마지막 user 메시지부터"로 자르면 요청은 빠지고 signal만 남아, 분류·만들기·칸 수정 바깥 턴이 도구를 부르지 않고 인사말만 했다. → signal이 아닌 마지막 user 메시지부터 자른다. 앞쪽 signal은 빼도 된다: `instructions` signal은 "바뀌었다"는 표지일 뿐이고 지시 원문은 system 프롬프트에 있다(Flue 문서 agent-api "Dynamic resources")

## 목표 메모 확인
- "한 달에 2kg 정도 천천히"를 첫 실행 1회는 `extreme_restriction`(무리한 목표)으로 잘못 분류했다(출력 33토큰, 선택지에 "한 달에 2kg 감량"). 그 뒤 5회는 모두 `done`(출력 21토큰)
- 그 실행은 대화 첫 메시지라 자르기가 걸리지 않았다. `FINISH_ONLY` 첫 줄을 단 뒤 6회 중 1회라, 모델(llama-4-scout) 출력이 흔들린 것으로 본다. B4(11-06) 확인은 3가지 메모 1회씩이었다

## 결론과 영향

- 목표 메모 오분류는 "나중에"에 남긴다. 무리한 목표로 잘못 보면 사용자는 목표를 다시 고르게 되고(막히지는 않음) 메모를 고치면 된다
