# B11 식단 생성 추론 수준 low vs medium (2026-11-07 밤)

## 질문

- 식단 생성·다시 추천의 추론 수준(`thinkingLevel`)을 Flue 기본값 `medium`에서 `low`로 낮추면 출력 토큰·시간·Neuron이 줄고 `checkPlan` 통과율은 유지되나 (T8-2)
- 11-06 배포본의 느린 생성(출력 14,832토큰, 5분 46초)을 추론 수준으로 막을 수 있나

## 방법

- 로컬 개발 서버(가짜 모드 끔), `.dev.vars`에 `PLAN_THINKING=low`(`models.ts` `planThinking`, Workers AI에 `reasoning_effort: "low"`로 간다), 새 로컬 토큰
- `npm run evals` (페르소나 A~D × 2 = 8회). 회차마다 인터뷰 제출 → 메뉴 분류(gemma, `INTERVIEW_THINKING` low 그대로) → 식단표 만들기
- 비교 대상 medium은 다시 돌리지 않고 같은 날 T1-7 결과 8회를 쓴다: A 2회([오전](2026-11-07-t1-7-eval-personas.md)) + B~D 6회([저녁](2026-11-07-t1-7-eval-personas-bcd.md)). 코드는 같고 추론 수준만 다르다
- 원본: [data/2026-11-07-b11-thinking-low.json](data/2026-11-07-b11-thinking-low.json). `experiments-recheck.test.ts`가 지금 규칙으로 다시 점검한다

## 비용

로컬 D1 카운터 증가분 약 3,460 Neuron(같은 시간대의 B10c 실험 바깥 턴 약 30~40 포함). 회차당 약 430. 23:56~00:37 KST, 약 41분.

## 결론과 영향

- **기본 추론 수준은 바꾸지 않는다** (계획의 기준: 8회 중 7회 이상 통과 + 약 25% 이상 감소). `PLAN_THINKING`은 시험용 설정으로 남긴다
- 생성 시간은 2~6분, 중앙값 약 3분이다. 기다리는 화면의 "4분쯤" 안내와 시간 예산(만들기 10분, 호출별 생성 8분)은 그대로 둔다
- 11-06의 14,832토큰 같은 긴 출력은 이번 16회에 없었다(최대 12,360). 느린 생성을 줄이려면 추론 수준이 아니라 다른 방법(프롬프트를 짧게, 칸을 나눠 만들기, 출력 상한)이 필요하다. 지금은 시간 예산이 대기 상한을 막고 있어 따로 task를 만들지 않는다

## 남은 의문

- 같은 프롬프트에서 출력 토큰이 2배 가까이 흔들리는 이유
- low C 2회차의 재요청 원인 (Flue 재요청이 다른 회차에도 숨어 있는지는 도구 `usages`의 입력 토큰으로 보인다. medium 8회에는 없었다)
