# MVP 이후 고도화 후보 (초안)

`docs/tasks.md`의 B1~B13과 T1-7까지를 MVP(기획서 "첫 시연" 범위)로 보고, 그 뒤에 붙일 만한 일을 모은다. 2026-11-07에 기획서, 스펙(0·2·3·10·11장), `plan-upgrade.md`, `tasks.md` "나중에" 절을 보고 정리했다.

> 초안이다. 범위, 순서, Neuron 어림은 나중에 다시 정리한다. 진행하기로 한 항목은 `tasks.md`의 task와 묶음으로 옮기고, 묶음을 시작할 때 CLAUDE.md 방식대로 계획을 먼저 써서 승인받는다.

## 지금 상태와 빈 곳

- MVP는 **한 번 쓰고 끝나는 흐름**이다. 인터뷰 → 분류 → 1주일 식단표 → 칸 수정까지 된다.
- 기획서 6장의 "계속 쓸 이유"(지난주를 이어서 짜기, 쓸수록 고칠 칸이 줄어듦)와 정식 운영 성공 기준(체크율 70%, 고친 칸 3개 이하인 주 비율)은 기능도 없고 잴 방법도 없다. 가장 큰 빈틈이다.
- 제약: 생성 1회 3~6분, 약 250~400 Neuron, 하루 무료 한도 10,000 (`plan-upgrade.md`).

## 추천 순서

1. **E2 로그인**
2. Neuron이 거의 들지 않고 가치가 큰 것: A1 지난 식단표 목록 → A2 체크 → A4 측정 기록, B1 태그 사전, E1 대화 기록 지우기
3. 실측이 필요하지만 효과가 큰 것: C1 외식 칸 코드 배치(B11 결과와 비교), C2 바깥 턴 조사, A3 체크 반영 생성
4. 기획서의 다음 기능: D1 하루 재조정 → D2 레시피 → D3 근육 증가 → D4 도시락
5. 사용자를 늘릴 때: C3 미리 만들기, E3 기관 통계, E4 요금제

로그인을 맨 앞에 둔 이유 (사용자 결정, 2026-11-07):

- A1·A2·A4는 여러 주에 걸친 사용자 데이터다. 링크를 잃으면 접근할 수 없는 지금 방식에 쌓기 전에 계정을 정한다
- E1(대화 기록 지우기)은 사용자별 대화 목록이 필요하다. 로그인과 같은 자리(사용자 식별, 가드, D1 `users`)를 고친다
- Neuron을 쓰지 않는다

## B. 결과 품질 ("코드가 보장한다" 원칙을 넓히기)

- **B1. 재료 → 태그 사전 (스펙 열린 질문 3).** 실측에서 태그가 여러 번 틀렸다(현미밥에 `refined_carb_main`, 백반·들깨에 `soy`, 소고기 볶음에 `fatty_meat` 빠짐). 칸의 `ingredients`로 코드 사전이 태그를 더하고 LLM 태그와 합친다. Neuron 0. 태그를 더하기만 하면 다시 추천이 늘 수 있으니, 지울 태그(오탐)를 따로 둘지 함께 정한다
- **B2. 주재료 반복 제한 ("나중에").** B1의 재료 정규화로 "닭가슴살 샐러드 / 닭가슴살 볶음" 같은 반복을 규칙으로 잡는다. `RULE_IDS`, 스펙 3.2·8.2 표를 함께 고친다
- **B3. 분류 이유 품질.** 기준 ID를 반드시 고르게 하고, 이유 문장은 코드 템플릿으로 바꾸는 방안("일반적인 식사라 부합함" 문제)

## C. 속도와 비용

- **C1. 외식 칸 배치를 코드로.** 외식 칸 메뉴는 목록, 분류, 주 1회 규칙, 연속 금지라는 정해진 제약 안에서 고르는 조합 문제라 코드가 보장할 수 있다. 코드가 `menuId`를 배치하고 LLM은 태그·주문 팁·이유만 채우거나 집밥 칸만 만든다. 출력 토큰과 다시 추천이 함께 줄어 B11(추론 수준)보다 효과가 클 수 있다. 태그 제한(튀김 횟수 등)은 LLM 태그에 달려 있어 점검은 그대로 둔다. 실측 1회 약 300 Neuron
- **C2. 바깥 턴 줄이기.** 화면이 정해진 접두어 메시지를 보내므로 바깥 모델은 사실상 도구 하나를 부를 뿐이다. 이 턴은 시간과 Neuron(2~21)을 쓰고, 대화가 길어지면 입력이 커지며, T10-2(병렬 호출) 위험도 만든다. Flue에서 도구를 직접 실행하거나 모델에게 결과를 짧은 요약만 보여 줄 수 있는지 `node_modules/@flue/runtime/docs/`부터 확인한다
- **C3. 미리 만들기.** 일요일 오후에 Cron Trigger로 다음 주 식단표를 만들어 두면 기다리지 않는다. 사용자가 늘면 Neuron 계획과 충돌하므로 안전선보다 낮은 별도 상한이 필요하다
- **C4. 진행 안내.** "몇 칸을 다시 고르는 중"(`useDataWriter`, "나중에"). 시간은 그대로지만 덜 답답하다

## E. 운영과 개인정보

- **E1. 대화 기록 지우기.** 건강 정보는 민감정보이고 기획서는 "언제든 지울 수 있게"를 약속했다. 지금은 프로필만 지워지고 Durable Object 대화는 남는다. 사용자를 늘리기 전에 한다
- **E2. 로그인 (스펙 열린 질문 2).** 지금은 고유 링크 토큰뿐이라 링크를 잃으면 데이터에 다시 들어올 수 없다
- **E3. 기관용 통계 (기획서 6장).** 개인 데이터 없이 이용 인원, 체크율 같은 집계만. A4가 먼저 있어야 한다
- **E4. 요금제 올리기.** `plan-upgrade.md`에 정리돼 있다. 더 큰 모델의 속도·정확도는 평가 세트로 비교한다

### E2 로그인: 시작 전에 정할 것

- **방식:** 이메일 매직 링크가 가장 가볍다. Cloudflare Email로 보내려면 보내는 도메인이 필요한데 지금 주소(`workers.dev`)로는 안 될 수 있어 확인이 필요하다. 도메인이 없으면 패스키, Cloudflare Access(소수 사용자)와 비교한다
- **기존 토큰 사용자 옮기기:** 지금 원격 토큰 1개의 사용자 ID와 저장된 프로필·식단표를 새 계정에 잇는 방법
- **가드와 계약:** 대화 ID 접두어(`<userId>-…`)와 하루 30회 제한은 그대로 두고, 토큰 확인을 세션 확인으로 바꿀지
